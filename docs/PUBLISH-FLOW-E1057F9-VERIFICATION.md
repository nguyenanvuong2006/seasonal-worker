## STRONGEST REMAINING CANDIDATE (unproven — recorded, not fixed)

The only way the shipped code can reach "ai-analyze 200, no error, no POST publish" is
`canConfirmPublish() === false`. All machine-check paths render an explicit red blocker
list; the **one** path that disables Confirm with *no* on-screen explanation is
**incomplete operator acknowledgements** — e.g. 4 of 5 boxes ticked. `describePublishBlockers()`
enumerates machine blockers only, so `publish-checklist-modal.tsx`'s own stated invariant
("NO SILENT DISABLE — every blocker that keeps Confirm disabled is listed here") does not
hold for the operator-ack dimension.

This is consistent with the evidence but **not proven** by it: the capture contains no
client-side checkbox telemetry. Proving or refuting it needs one of:

1. the operator's screen state at the moment Confirm was pressed (how many boxes ticked), or
2. a browser console / error-boundary capture from the failing session, or
3. a `console.debug` of `{machineChecksPassed, checks, loading, confirming}` added behind a
   flag and re-captured in Production.

Until one of those exists, changing the gate would be a guess, and Phase 5 forbids it.
